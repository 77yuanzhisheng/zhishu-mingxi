# 大题自动批阅引擎设计

## 目标

在 `POST /api/grading/grade` 提供可审计的大题批阅能力。输入学生作答和题目上下文，输出五维评分、总分、错误类型及评语，并写入 `grading_results`。当调用方仅给出 `question_id` 时，引擎从队员 2 的结构化题库补足题面、标准答案、知识点和评分要点。

## 题源与评分要点

引擎直接复用 `backend.kb.structured` 的模块函数和 `GRADING_GUIDE` 数据，而不是通过本服务的 HTTP 回环调用：

- 用 `get_structured_questions(limit=10000)` 查询题目 ID。
- 用知识点 `kp` 获取 `GRADING_GUIDE[kp]`，并把 `focus`、`checks`、`common_errors` 序列化到 LLM 提示词。
- `question_id` 不存在时返回 404；调用方同时传直接题目字段时允许无需题库题 ID 的临时评分。

## 评分链路

使用三阶段、可校验的 LLM JSON 输出：

1. 分析：提炼学生的关键步骤、遗漏与错误候选。
2. 评分：按照结论正确性 20、关键推理步骤 35、逻辑严密性 25、定义定理使用 10、表达与符号规范 10 分别打分，生成证据与错误类型。
3. 复核：验证总分、维度、错误归类和评语是否与证据一致。

每阶段 JSON 解析失败时最多请求一次格式修复；服务端仍独立校验分数有限、范围正确、五维齐全、总分等于分项之和、错误类型受限且证据位置有效。模型不可用或输出持续不合法时，返回明确的 503/502，不得以伪评分替代。

## 数据与评测

`grading_results` 记录请求上下文、五维评分、总分、错误类型、评语、分析与复核记录、模型身份、提示词版本、耗时和尝试次数。人工标签单独保存和校验，只有真实人工标签存在时才计算模型与人工的总分/维度 MAE、错误类型 F1、等级 Cohen kappa。

队员 2 的 112 题 `模型作答 + 模型评分` 结果仅作为模型作答基线，不能宣称是批阅准确率或人工一致性；报告在没有人工标签时明确标记为待交叉验证。

## 非目标

本次不改动前端、不接入多模态输入、不调整当前 8B/后续 27B 的基础连接配置，也不推送远端。实现完成后仅本地提交，供队长审阅、合并。
