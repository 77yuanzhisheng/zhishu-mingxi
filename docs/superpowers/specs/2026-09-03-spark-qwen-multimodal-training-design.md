# 星火 MaaS + Qwen 离散数学多模型方案设计

日期：2026-09-03
状态：待用户确认后进入实施

## 1. 目标

将“知数·明析”调整为以星火 MaaS 为比赛主线：

- 在星火 MaaS 对 Qwen3-32B 使用 SFT-LoRA 微调；
- 用微调后的 Qwen3-32B 负责离散数学文本问答、证明、计算、批阅、错误诊断和学习路径解释；
- 用 Qwen3-VL-32B-Instruct 负责题目图片、手写答案、公式和离散数学符号识别；
- 通过统一 LLM 接口接入现有后端，不改写 RAG、批阅和学习路径业务核心；
- 证明题完整响应目标控制在 30 秒以内，并保留可量化测试记录。

## 2. 系统边界

### 2.1 主流程

```text
文字问题 ───────────────────────┐
                                ▼
图片题目/答案 → Qwen3-VL-32B → 结构化文本/LaTeX/符号
                                ▼
知识库检索 + 符号规则 + 批阅规则
                                ▼
星火 MaaS 微调后的 Qwen3-32B
                                ▼
问答 / 证明 / 计算 / 批阅 / 学情诊断 / 学习路径
```

### 2.2 模型职责

| 模型 | 职责 | 是否作为 MaaS 微调主模型 |
|---|---|---|
| Qwen3-32B | 数学文本推理、问答、证明、计算、批阅 | 是，SFT-LoRA |
| Qwen3-VL-32B-Instruct | 图片、手写答案、公式和符号识别 | 否，先作为视觉 API |
| Qwen3-Reranker-8B | 知识库候选片段重排序 | 后续可选 |
| Qwen3-Embedding-8B | 知识库向量化 | 后续可选 |

## 3. 微调数据设计

第一版只使用文本 SFT 数据，不把图片伪装成文本训练样本。数据覆盖：

1. 离散数学概念问答；
2. 证明题标准解答；
3. 计算题分步解答；
4. 学生错误答案与错误诊断；
5. 五维大题批阅；
6. 离散数学符号规范和推理规则；
7. 教学解释和下一步学习建议。

数据字段按平台实际要求转换为 JSONL；默认采用 `messages` 格式，每条样本包含 `system`、`user`、`assistant` 三类消息。训练集、验证集、固定测试集分离，避免把测试答案泄漏到训练集。

## 4. 符号体系要求

训练数据统一遵守：

- 量词：`∀`、`∃`；
- 逻辑：`¬`、`∧`、`∨`、`→`、`↔`；
- 集合：`∈`、`∉`、`⊆`、`⊂`、`∪`、`∩`、`\`、`ᶜ`；
- 关系与函数：`R`、`aRb`、`f: A → B`；
- 图论：`V`、`E`、`deg(v)`、路径、连通、树；
- 证明必须区分定义、已知条件、推理步骤和结论。

符号表和推理规则既进入训练样本，也保留为后端可审计规则，不把关键评分约束完全交给模型。

## 5. 后端接入设计

业务层继续依赖统一接口：

```python
llm.generate(messages)
llm.stream(messages)
```

模型提供商通过环境变量选择，比赛默认星火：

```env
LLM_PROVIDER=spark
SPARK_BASE_URL=<星火实际接口地址>
SPARK_API_KEY=<不提交到仓库>
SPARK_MODEL=<发布后的模型标识>
SPARK_VL_MODEL=<视觉模型标识>
```

不在代码中写入密钥，不删除 Qwen 服务器实验脚本；Qwen 本地服务仅作为历史基线/备用，前端和文档的比赛主线改为通用“星火 Qwen 模型”，清理旧的 Qwen3-8B 和 SiliconFlow 主线文案。

## 6. 视觉接口设计

视觉识别输出统一为结构化结果：

```json
{
  "question_text": "",
  "student_answer": "",
  "latex": [],
  "symbols": [],
  "confidence": 0.0,
  "warnings": []
}
```

视觉服务只负责识别和规范化，不直接决定最终分数。识别结果先经过符号校正和必要的人工确认，再进入 Qwen3-32B 推理/批阅。

## 7. 性能目标

首版验收指标：

- 证明题完整文本响应：不超过 30 秒；
- 计算题完整文本响应：不超过 30 秒；
- 证明题/计算题批阅：不超过 30 秒；
- 流式首字响应：尽量不超过 5 秒；
- JSON 批阅格式成功率：不低于 95%；
- 视觉识别与文本推理分别记录耗时；
- 记录模型名、输入输出 token、首字延迟、总延迟、错误和重试。

采用限制输出长度、压缩上下文、流式响应、超时和有限重试控制时延；不承诺在训练完成前的真实 API 延迟一定达标，必须以实测报告为准。

## 8. 实施阶段

### 阶段 A：训练准备

- 确认 Qwen3-32B 的 MaaS 数据格式和资源限制；
- 生成并人工抽查训练/验证/测试 JSONL；
- 记录数据版本和符号规范版本；
- 提交 SFT-LoRA 训练任务。

### 阶段 B：训练与发布

- 监控排队、训练状态、损失和平台错误；
- 训练完成后发布模型服务；
- 保存模型标识、版本、训练参数和发布时间。

### 阶段 C：后端接入

- 增加星火文本/视觉配置；
- 保持现有业务接口兼容；
- 增加模型能力探测和清晰错误提示；
- 接通问答、RAG、批阅和学习路径。

### 阶段 D：验证

- 固定题集测试概念、计算、证明、批阅和视觉识别；
- 对比微调前后正确率、符号规范、JSON 成功率和延迟；
- 使用人工评分数据计算 MAE、维度误差和一致性指标；
- 形成比赛可展示的实验记录。

## 9. 暂不纳入

- 不再继续投入双 V100 上的 27B 本地部署作为比赛主线；
- 不把 Qwen3.6-35B-A3B 作为 MaaS 微调主模型，因为其详情页训练方式显示为 `--`；
- 不把 Qwen3-235B、Qwen3.5-397B 或 Coder 模型作为当前主线；
- 不在第一阶段引入新的 Embedding/Reranker，除非现有 RAG 测试证明确有必要；
- 不将 API 密钥、模型资源 ID 或账号信息写入 Git。

## 10. 验收标准

只有同时满足以下条件，才认为本阶段完成：

1. MaaS 训练任务成功完成并发布服务；
2. 后端能通过统一接口调用发布后的 Qwen3-32B；
3. 图片输入能通过 Qwen3-VL-32B 转为结构化文本；
4. 证明题、计算题、问答和批阅链路跑通；
5. 真实测试记录明确显示哪些请求在 30 秒内、哪些未达标；
6. 配置、数据版本、模型版本和测试结果可追溯。
