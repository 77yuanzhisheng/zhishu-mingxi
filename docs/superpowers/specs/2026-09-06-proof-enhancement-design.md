# 离散数学通用证明增强与低延迟自检设计

日期：2026-09-06

## 1. 目标

在不针对固定评测题硬编码答案的前提下，提升“知数·明析”对未见离散数学问题的证明正确性、严谨性、符号一致性和教学可读性；同时保持证明题端到端响应时间不超过 30 秒，并尽量不增加当前约 12 秒的平均响应时间。

本轮优化关注模型能力，而不是单纯提高某一批测试题的分数。现有专项测试平均约 9.0/10，主要扣分来自证明步骤不严谨、定理条件遗漏、特殊案例与一般结论混淆，以及个别图论/着色表述不准确。

## 2. 非目标

- 不把现有 112 题答案写入规则或代码。
- 不修改 API Key、模型服务配置或视觉模型配置。
- 不在没有对照实验的情况下重新训练模型。
- 不通过删减证明步骤、隐藏错误或降低评分标准来制造分数提升。

## 3. 设计原则

### 3.1 通用优先

增强规则按证明任务的结构和错误类型组织，而不是按题目文本匹配。规则应适用于集合、关系、逻辑、图论、代数结构、计数与着色等未见题目。

### 3.2 先规划、后生成、再校验

请求链路生成轻量证明计划，模型据此回答；回答完成后执行低成本结构和逻辑一致性检查。只有检测到明确风险时才触发一次定向修订，正常回答不增加额外模型调用。

### 3.3 速度预算

- 默认路径：保持一次主模型调用，不增加二次模型调用。
- 轻量检查：使用本地规则、符号校验和已有推理工具完成，目标耗时小于 100 ms。
- 仅在高风险错误信号同时出现时触发一次修订调用。
- 总响应时间硬上限保持 30 秒；超时则返回已生成答案并标注需要复核，不阻塞用户。
- 记录主调用、校验和修订各阶段耗时，便于后续对比。

## 4. 证明回答协议

对被识别为证明/推导/反例/定理应用的问题，系统提示词要求模型优先采用以下结构：

1. **题意与目标**：明确需要证明、构造或反驳的命题。
2. **已知条件与定义**：只列出本题实际给出的条件，并展开关键定义。
3. **证明策略**：说明直接证明、逆否命题、反证、构造、归纳或分类讨论等方法。
4. **逐步推导**：每个关键结论都给出依据；公式中的变量和逻辑符号保持一致。
5. **边界/反例检查**：检查定理条件、极端情况以及是否把特例推广成一般结论。
6. **结论**：明确回扣原命题，说明已完成证明或指出命题不能由条件推出。

规则要求模型：

- 不虚构定理、论文、编号或“显然成立”的关键跳步。
- 使用外部定理时，先说明定理内容以及本题为何满足其条件。
- 题目要求证明一般命题时，不能只验证一个例子。
- 无法证明或题目本身可能不成立时，应优先寻找反例并明确说明。
- 不暴露内部思维链；只输出对用户有帮助的可核验步骤和简洁依据。

## 5. 题型专项约束

### 5.1 图论与哈密顿性

回答删除顶点、连通分支和哈密顿图问题时，必须区分“回路”“路径”“连通分支”三个概念。典型论证应说明：若图有哈密顿回路，删除一个顶点后，回路变为覆盖剩余顶点的路径，因此剩余图至少包含一条覆盖所有顶点的连通子图；再结合题目给出的分支数量推出矛盾。禁止把哈密顿回路删除顶点后直接表述成“每个连通分支都是一条路径”。

### 5.2 平面图与四色定理

涉及四色定理时，必须分别说明：

- 题目对象是否为平面图或平面地图；
- 使用的是顶点着色还是地图区域着色；
- 当前构造是否只是一个例子的合法着色；
- 一个 `K4` 的着色不能代替四色定理对所有平面图的证明。

涉及 `K4` 时，应优先给出明确的平面嵌入或事实依据，不使用不充分的边数估计冒充平面性证明。

### 5.3 集合、关系与逻辑

涉及 `∀`、`∃`、`∧`、`∨`、`→`、`¬`、`⊆`、`∪`、`∩` 等符号时，要求先统一符号，再逐项展开定义；对包含关系、等价关系和量词否定尤其检查方向、量词范围和必要/充分条件是否颠倒。

### 5.4 代数结构

使用群、子群、同态、阶等结论时，必须验证封闭性、单位元、逆元、有限性或阶的假设是否确实存在。若可以直接构造对象，优先展示构造过程，避免调用不必要的强定理。

## 6. 轻量自检器

在现有回答评估链路上增加可组合的检查项，并返回结构化元数据：

- `proof_structure`: 是否包含目标、依据、推导和结论；
- `theorem_conditions`: 是否出现未验证的关键定理条件；
- `symbol_consistency`: 关键逻辑符号和变量是否前后一致；
- `counterexample_awareness`: 是否存在需要反例/边界检查但回答完全遗漏的信号；
- `domain_guard`: 是否触发图论、四色定理、集合逻辑或代数专项约束；
- `revision_needed`: 是否达到触发修订的阈值。

检查器只做保守的风险识别，不声称替代形式化定理证明器。高风险判定需要多个独立信号共同满足，避免因正常的简洁回答而增加延迟。

## 7. 定向修订策略

仅当自检发现明确问题时，向同一次模型服务发起一次短修订请求，要求“保留正确内容，只修复列出的逻辑问题，并按证明协议重写”。修订请求不重新生成无关内容，也不改变题意。

若修订失败、超时或服务不可用，返回主答案，并保留风险元数据供前端或教师端复核。不得因自检失败而让正常问答不可用。

## 8. 评测与验收

验收分为四组：

1. **未见证明题**：集合、关系、逻辑、图论、代数、着色各覆盖不同难度。
2. **错误诱导题**：题目包含容易误用的定理、缺失条件或看似合理的错误结论。
3. **教学表达题**：检查步骤是否可理解、符号是否规范、结论是否回扣目标。
4. **回归集**：现有 112 题及已发现的专项题，确保不退化。

记录：

- 正确性与人工评分；
- 关键步骤完整性；
- 定理条件核验率；
- 符号一致性；
- 平均、P95 响应时间；
- 30 秒内完成率；
- 修订触发率及修订成功率。

最低验收要求：

- 未见题和回归集的正确性不下降；
- 复杂证明的严谨性有可观察提升；
- 平均响应时间不超过当前基线的 1.25 倍；
- 30 秒内完成率保持 100% 或至少不低于现有结果；
- 不出现新增的 API Key、密钥或服务配置泄漏。

## 9. 实施边界

第一阶段只改证明提示协议、轻量自检器、定向修订入口和测试；不改模型服务供应商、不改视觉模型、不改前端协议。完成第一阶段并通过评测后，再根据未见题错误样本决定是否准备新一轮 LoRA/SFT 数据。
