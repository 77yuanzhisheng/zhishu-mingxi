## 二、功能规格

### 2.1 学习记录 / 做题记录采集（补全数据层）

**现状**：只有 `node_mastery`（节点聚合：level/correct_count/total_count），无逐题记录。

**新增 `answer_events` 表**（backend/learning/database.py 迁移）：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| user_id | 学生 |
| question_id | 题号（自测题/考试题/批阅题） |
| question_type | single / fill / calc / proof / exam |
| module / node_id | 所属模块与知识节点 |
| is_correct | 是否答对（自测/选择题） |
| duration_ms | 答题耗时 |
| answer_text | 答案原文（大题批阅时提交的文本） |
| created_at | 时间戳 |

**API**：
- `POST /api/learning/events` — 采集答题事件（前端自测练习、考试、批阅统一上报）
- `GET /api/learning/events?user_id=&limit=` — 做题历史时间线（前端展示）
- 保留现有 `update-mastery`（聚合层仍由它维护）

**量化指标**：事件采集完整率（自测/考试/批阅三处均上报）、答题耗时分布、正确率时间曲线。

### 2.2 能力评估画像（学生能力模型）

**API**：`GET /api/learning/ability-profile?user_id=`

**输出**（雷达图数据）：
```json
{
  "overall": 72,                          // 综合能力 0-100
  "level": "良好",
  "modules": [
    {"module": "propositional_logic", "name": "命题逻辑", "score": 85, "level": "熟练",
     "mastered_nodes": 8, "total_nodes": 9, "accuracy": 0.92, "practice_count": 41},
    {"module": "graph_theory", "name": "图论", "score": 54, "level": "薄弱",
     "mastered_nodes": 4, "total_nodes": 12, "accuracy": 0.61, "practice_count": 18}
  ],
  "weakest_modules": ["graph_theory", "relations"],
  "trend": [{"date": "...", "overall": 60}, ...]   // 能力变化曲线
}
```

**评分规则**：
- 模块能力值 = 加权（掌握节点占比 50% + 正确率 30% + 练习量 20%），0-100
- 等级：≥85 优秀 / 70-84 良好 / 50-69 及格 / <50 薄弱
- 综合能力 = 各模块加权平均（按学习进度权重）

**量化指标**：能力值与考试得分相关性（Pearson r）、前后测提升幅度。

### 2.3 个性化学习路径（薄弱点驱动）

**复用/增强**：`backend/kb/recommender.py` 已有 `recommend_learning_path`（按依赖拓扑）。

**增强**（配合能力画像）：
- 输入：能力画像中的薄弱模块/节点 + 依赖拓扑
- 输出：有序路径 `[{node_id, name, step, action: "复习|练习|挑战", recommended_questions: [...]}]`
- 策略：先依赖基础（如命题逻辑是谓词逻辑前提）→ 再薄弱节点 → 配难度梯度（level-1 巩固 → level 强化 → level+1 挑战）

**API**：`GET /api/learning/path?user_id=`（内部调 recommender + 能力画像）

**量化指标**：路径推荐题命中率（推荐题 vs 后续实际错题）、按路径学习后能力值提升 Δ。

### 2.4 大题自动批阅（证明/计算题，LLM 数学推理验证）⭐核心亮点

**API**：`POST /api/grading/grade`
```json
{
  "question": "证明：若 a,b 都与 c 可交换，则 a∘b 也与 c 可交换。",
  "student_answer": "...学生的证明...",
  "reference_answer": "标准答案（可空，有则参与比对）",
  "kp": "semigroup", "module": "代数结构", "max_score": 10
}
```

**响应**：
```json
{
  "score": 8.5, "max_score": 10,
  "dimensions": [
    {"name": "结论正确性", "weight": 0.2, "score": 2.0},
    {"name": "关键推理步骤", "weight": 0.35, "score": 3.0},
    {"name": "逻辑严密性", "weight": 0.25, "score": 2.0},
    {"name": "定义/定理使用", "weight": 0.1, "score": 1.0},
    {"name": "表达与符号规范", "weight": 0.1, "score": 0.5}
  ],
  "comment": "整体思路正确，但第 3 步缺少对交换律使用条件的说明……",
  "error_types": ["跳步", "未说明定理适用条件"]
}
```

**评分方法**：
- LLM-as-judge：用 SiliconFlow Qwen3 按 5 维规则评分（JSON 输出）
- 规则约束：结论正确给结论分；关键步骤逐条比对标准答案（有标准答案时）；检测循环论证/跳步/错用定理/符号错误
- 一致性校验：同一答案多次评分方差、与人工评分 Cohen's κ
- 落库：`grading_results` 表（答题人、题、分、维度、评语、时间）

**量化指标**：与教师人工评分一致性 κ≥0.7、各维度平均分、错误类型分布、批阅耗时（目标 <30s/题）。

### 2.5 112 题评测基准（证明系统与模型的强度）⭐

**脚本**：`scripts/benchmark_proofs.py`
- 输入：`data/documents/老师训练题库.json`（112 题全量，或 proof/calc 子集）
- 流程：题面 → 调 LLM 作答 → 调批阅引擎自评 → 汇总
- 输出：`scripts/benchmark_results.json` + Markdown 报告
- 指标：各模块得分率、正确率、耗时、超时率、RAG 开/关对比、错误类型分布

**演示数字目标**：证明题总体得分率 ≥65%，数理逻辑模块 ≥80%，RAG 增益 ≥20%。
